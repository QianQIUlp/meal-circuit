# MealCircuit v0.3.1

MealCircuit v0.3.1 is the supported external-use baseline for the local-first Windows x64 desktop/Python and native Android clients. These are the only maintained release targets. It replaces v0.3.0, closes the known vulnerable desktop dependency, makes fresh installation self-checks truthful, and makes the release pipeline fail closed on tests, signatures, legal notices and artifact completeness.

## Choose an asset

| Platform | Release asset | Intended use |
| :--- | :--- | :--- |
| Windows x64 | `MealCircuit-0.3.1-windows-x64-setup.exe` | Install the Authenticode-signed desktop app. Verify the publisher before continuing. |
| Windows x64 | `MealCircuit-0.3.1-windows-x64-portable.zip` | Extract and launch the signed `MealCircuit.exe` without an installer. |
| Android 8.0+ | `app-release.apk` | Install the release-signed APK directly on a device. |
| Android distribution | `app-release.aab` | Upload to Play Console or another bundle distributor; it is not directly installable. |

Those four platform artifacts plus `SHA256SUMS.txt` and `MealCircuit-v0.3.1.cdx.json` are the exact six public release assets. Verify the SHA-256 entry for every downloaded executable or package before opening it. The SBOM is generated from the canonical Python and Android lock files and covers resolved dependency versions rather than merely inventorying archive filenames.

## What is ready in this baseline

- A new user can initialize a private home, pass `doctor`, complete the seven-step safety and preference setup, and use Today, Plans and Me from the Windows Web/desktop client.
- The Web interface is responsive at narrow mobile widths, including the theme control on the Me page.
- Windows packages include the runtime rules, templates, protocol contracts, project notices and applicable third-party legal text. Android exposes the corresponding legal notices from the app.
- Wheel and source distributions include all runtime resources, contain no cached bytecode, and are checked through an isolated install before release.
- `cryptography` is resolved at 50.0.0; the v0.3.0 Windows package containing 49.0.0 is superseded and must not be redistributed.
- Android remains an offline native client and accepts only reviewed daily plans published by the authoritative Python/Windows desktop seven-stage workflow.
- Portable Data temporary paths, OpenAPI generation, PostgreSQL recovery fixtures, Android release authority and Windows frozen metadata have dedicated regression coverage.

## Planning boundary

MealCircuit is an agent-in-the-loop workbench, not a bundled AI subscription. Without an external agent or a model provider and API key that the user explicitly configures, it records facts, status, preferences and personal context but does not generate a next-day plan by itself. Android does not run the seven-stage planner locally; it displays and records against plans produced and accepted through the Python/Windows desktop workflow.

Built-in model generation is opt-in. Keys remain in the current Python process and are not written to SQLite, files, logs, pages, Portable Data or Sync data. Context or photos sent through this option are processed under the selected model provider's data policy.

## Upgrade and recovery

Export an encrypted `.mcx` archive before upgrading and rehearse a restore using `docs/backup-restore.md`. The desktop client creates a SQLite Backup API snapshot before schema migration; Android Room migrations preserve existing Domain data. Keep the recovery string separate from every device before enabling Sync.

Sync is disabled by default. There is no official hosted service: deploy `sync_server/compose.yaml` or use another compatible Sync v1 endpoint. Losing all authorized devices and the recovery string makes remote ciphertext unrecoverable by design.

## Security and release trust

The public release is created only after the same tag's full Python/PostgreSQL/Android quality workflow succeeds, the Windows packaged smoke test and Android package checks pass, release assets match the exact six-item manifest, dependency audits report no known vulnerability and required legal materials are present.

- Android APK and AAB publishing requires the configured release keystore and strict signature verification.
- Windows publishing requires an Authenticode certificate; unsigned Windows output can be used in local or pull-request testing but cannot become a tagged release.

Remote Sync entities and assets are encrypted on clients with AES-256-GCM and opaque HMAC-derived identifiers. API keys, recovery strings, Account Data Keys and authentication tokens are excluded from Domain and Portable Data. This implementation has cross-language vectors and negative tamper tests but has not received an independent third-party cryptographic audit.

MealCircuit provides general logging and decision support, not medical diagnosis or treatment. Health states, allergies, targets and other high-impact constraints take effect only after explicit user confirmation.
