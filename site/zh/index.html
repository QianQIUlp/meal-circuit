长期反馈回路

先看事实，再读上下文，最后才给建议。

每日计划不能从一份模型回复直接发布。MealCircuit 会依次分开事实、个案理解、专业边界、策略选择、计划设计和独立审查，之后再交给你接受。

  1. 01 记录现实

    事实保持事实

    记录餐食、照片、原材料、饥饿、睡眠、训练、身体反应和用户更正，不用伪造的精确数值填补未知。

  2. 02 理解个体

    读懂具体的人

    把当前目标、个人总纲、近期趋势、当天约束和已确认偏好放入同一份决策上下文。

  3. 03 设计选择

    比较真实方案

    综合安全、份量、训练恢复、用餐方式、准备时间和食材承接，再设计经过审查的次日草案。

  4. 04 持续校准

    从执行结果学习

    保留每次更正和执行反馈；重复需求只有在证据足够时，才成为可见、可撤销的个人理解。

默认保留数据主权

让历史持续发挥作用，不必先交给别人的云。

本地数据库始终是事实来源。同步和模型调用是彼此独立的选择，哪些数据会离开设备都有明确边界。

阅读隐私说明 ↗
本地

默认本地运行

Windows 桌面端和 Android 端只读写各自本地数据库，核心功能离线可用。

默认启用
密

可选端到端加密同步

兼容的自托管中继只保存加密修订和照片分块，不执行饮食规划逻辑。

按需配置
AI

模型访问必须显式开启

由你选择服务商、模型和 API Key；密钥只在当前进程存在，不写入持久化数据。

主动选择

三个日常入口

把复杂机制留在每次决定的背后。

普通导航只聚焦现在真正重要的三件事：今天、计划，以及正在影响计划的个人上下文。

01 · 今天

发现变化。

查看当天安排、记录实际变化、只回答真正相关的问题，并共同调整明天的草案。

02 · 计划

带着上下文行动。

查看当前和历史计划，在生活条件变化时调整一餐，并记录这次选择实际执行得怎样。

03 · 我的

掌握自己的规则。

管理目标、用餐方式、安全边界、库存、已学偏好、界面外观和高级设置。

诚实的能力边界

提供真实帮助，不制造虚假确定性。

MealCircuit 让未知保持可见。安全规则和用户确认是产品流程本身，而不是生成结束后的补充说明。

×

不做医学诊断

它提供一般性的记录和决策协助，不提供诊断或治疗建议。

×

不编造不可见事实

油、酱汁、重量、品牌、健康状态和库存，在有证据前保持未知。

×

不提供官方托管云

账户只服务于用户自行配置的兼容自托管同步。

×

不捆绑规划模型

没有你的 Agent 或主动配置的模型 API Key 时，MealCircuit 会记录上下文但不会生成明日安排；Android 只消费 Python/Windows 桌面流程审查后的计划。

×

不静默发布计划

通过审查的草案仍可替换，只有用户明确接受后才成为正式计划。
